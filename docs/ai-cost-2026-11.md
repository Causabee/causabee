## What the ledger cannot say yet

- **Which job a request was for.** Reading what comes in, the brief and next step, or the chat: no request carries its job. Without that, the cheapest model cannot be chosen per job, and the savings cannot be measured per job.
- **Its second rows count tokens twice.** A request paid partly or wholly from top-ups gets two rows, and both carry its tokens (`server/beeserver/src/index.ts:199–209`). The dollars are right; token and request counts summed over both kinds are too high. Parked for the fix lane.

## The queries

Run in Cloudflare › Storage & Databases › D1 › beeserver › Console.

```sql
-- per day
SELECT substr(time,1,10) AS day, COUNT(*) AS requests, ROUND(SUM(micros)/1e6, 3) AS dollars,
       SUM(tokens_in) AS tokens_in, SUM(tokens_cached) AS cached, SUM(tokens_out) AS tokens_out
FROM ledger WHERE kind IN ('spend','spend_extra') GROUP BY day ORDER BY day;

-- per model
SELECT model, COUNT(*) AS requests, ROUND(SUM(micros)/1e6, 3) AS dollars,
       SUM(tokens_in) AS tokens_in, SUM(tokens_cached) AS cached, SUM(tokens_out) AS tokens_out
FROM ledger WHERE kind IN ('spend','spend_extra') GROUP BY model ORDER BY dollars DESC;

-- per month and kind: real requests are the "spend" rows
SELECT period, kind, COUNT(*) AS rows, ROUND(SUM(micros)/1e6, 3) AS dollars,
       SUM(tokens_in) AS tokens_in, SUM(tokens_out) AS tokens_out
FROM ledger GROUP BY period, kind ORDER BY period, kind;
```
